# Contract surfaces

Load-bearing names other code and tests depend on. A rename here is a breaking
change: grep the registry before touching one, and add a row when a new shared
entry point ships.

## Test harness

| Name | File | Contract |
|------|------|----------|
| `createOwnerClient()` | `tests/helpers/auth.ts` | Signs up a fresh, distinct owner and returns `{ client, userId, email, password }` — an anon-keyed client under that owner's RLS. Never service-role. |
| `createAuthenticatedCookieHeader()` | `tests/helpers/session.ts` | Mints a fresh owner and returns the genuine (possibly chunked) `sb-<host>-auth-token` Cookie header a browser would send. |
| `createAuthenticatedOwner()` | `tests/helpers/session.ts` | As above, plus the owner's anon-keyed client, so a test can drive an authenticated route and verify its DB side-effect as the same owner. |
| `corruptCookieHeader(header)` | `tests/helpers/session.ts` | Turns a captured header into a present-but-invalid session, keeping the captured cookie name so the negative case cannot pass for the wrong reason. |
| `runMiddleware({ pathname, cookieHeader })` | `tests/helpers/middleware.ts` | Drives the real `src/middleware.ts` `onRequest` and returns `{ response, nextCalled, locals }`. |
| `createAnonClient()` | `tests/helpers/auth.ts` | An anon-keyed client with **no session**, so it carries the `anon` role — the caretaker's actual identity. The only way to assert what a link-holder can and cannot reach. |
| `createOwnerWithPet()` | `tests/helpers/auth.ts` | An owner plus one pet, inserted through that owner's own client. Every care period needs at least one pet (S-08), so this is the seeding primitive for three suites; without it each grows its own copy. |
| `createAuthenticatedOwnerWithPet()` | `tests/helpers/session.ts` | The same, plus the genuine session Cookie header — for route tests that both drive a handler and need a pet the owner really owns. |

## Application

| Name | File | Contract |
|------|------|----------|
| `PROTECTED_ROUTES` | `src/middleware.ts` | Path prefixes the middleware gates. Exported so the auth-gating suite covers every prefix from this one list — a new route gets regression coverage without editing the test. |
| `createClient(headers, cookies)` | `src/lib/supabase.ts` | The request-scoped, cookie-bound Supabase client. Publishable key only — see `docs/reference/data-access.md`. |
| `create_pet_with_instructions` | `supabase/migrations/` | Security-invoker RPC that writes a pet and its instructions atomically. |
| `create_period_with_slots` | `supabase/migrations/` | Security-invoker RPC `(p_title text, p_start_date date, p_end_date date, p_token_digest text, p_pet_ids uuid[], p_caretaker_note text default null)` that writes a care period, its pet links and every generated slot in one transaction. Raises if `p_pet_ids` names no pet after NULLs are stripped — that raise is the **only** enforcement of "a period covers at least one pet". Security-invoker on purpose: RLS on `care_period_pets` is what refuses a pet the caller does not own, rolling the period back with it. The trailing note parameter is defaulted so five-argument callers stay valid; grants are per-signature, so any further change is DROP + CREATE + an explicit revoke/grant pair (S-03 Phase 1). |
| `care_slots` claim columns | `supabase/migrations/` | `claimed_by_name`, `claimed_at` and `claim_digest` are ONE fact, tied by `care_slots_claim_complete`: all three null (free) or all three set (taken). `care_slots_claim_digest_format` pins the digest to 64 lowercase hex chars, because the reveal will be an equality test and a mixed-case digest would silently never match. Both constraints are live and pinned by `tests/rls/care-slots.isolation.test.ts`. **`claim_digest` has no reader or writer yet** — it ships empty in S-03 Phase 1 and is intended to hold the hex SHA-256 of the caretaker's capability secret, answering "is this slot *mine*?", which `claimed_by_name` cannot (unbounded, non-unique, unverified). ⚠️ **One capability = one identity is NOT held by the schema.** Nothing stops one `claim_digest` from carrying two different `claimed_by_name` values in the same period (verified in psql; impl-review F1) — a multi-row invariant no CHECK can express. Phase 2's claim function is the **only** intended enforcement, the same posture as "at least one pet" in `create_period_with_slots`. A direct owner UPDATE can still break it. |
| `care_periods.caretaker_note` | `supabase/migrations/` | Free text about the TRIP rather than a pet (the design's NOTATKA). Bounded at 2000 chars by `care_periods_note_length` and mirrored by `MAX_NOTE_LENGTH`. `""` is normalised to NULL in `createPeriodSchema`, so `caretaker_note is null` is an honest "no note" test. Written by `create_period_with_slots`, read back to the owner on `/periods/[id]`. **Intended as the sensitive tier from S-03 Phase 3** — to be served by `get_claimed_details` to a holder of a matching claim secret and never by `get_period_by_token`. That function does not exist yet; today the note reaches no caretaker at all, because `get_period_by_token` builds a named `jsonb_build_object` that omits it. |
| `get_period_by_token` | `supabase/migrations/` | The **only** anon-reachable surface in the schema. Security-definer; resolves at most one active period from a raw invite token and returns it with its slots' free/taken state. Returns NULL for unknown, malformed and revoked tokens alike. Future caretaker capabilities extend this function — never an anon policy. |
| `regenerate_period_token` | `supabase/migrations/` | Security-invoker RPC that replaces a period's token digest, invalidating the previous link. Returns the period id, or NULL when RLS filtered the row out. |
| `generateInviteToken()` / `digestInviteToken()` | `src/lib/invite-token.ts` | Mints a base64url 32-byte token and derives its hex SHA-256. The digest encoding must stay byte-identical to `encode(sha256(convert_to(token,'UTF8')),'hex')` in `get_period_by_token`. |
| `care_period_pets` | `supabase/migrations/` | Join table making a care period cover the owner's chosen pets. Its four RLS policies are a **conjunction over both parents** — the caller must own the period AND the pet. Either half alone is an IDOR that stays invisible until S-03 ships the instruction reveal; `tests/rls/care-period-pets.isolation.test.ts` pins both directions. |
| `Chip` | `src/components/ui/Chip.tsx` | The design's pill. `onToggle` present renders a `<button>` with `aria-pressed` (the create form's pet selector); absent renders a `<span>` (the two owner screens, where the card itself is the `<a>` and a nested button would be invalid HTML). Geometry is the design's KTÓRE ZWIERZĘTA chip; the unselected and read-only tones are built from the same tokens so all three themes follow without a second definition. |
| `MAX_PETS_PER_PERIOD` | `src/lib/period-format.ts` | Upper bound on pets per trip, shared by the zod schema and the chip selector so client and server cannot drift. The RPC has no bound of its own: a caller can only link pets they own, and RLS already caps that. |
| `PERIOD_MESSAGES` | `src/lib/schemas/period.ts` | Every user-facing message `createPeriodSchema` can produce. `POST /api/periods` returns one of these and `NewPeriodForm` renders it verbatim, so the set is a contract — `tests/unit/period-schema.test.ts` asserts membership, which fails on any zod default (a "looks English" heuristic does not: zod's format defaults are "Invalid UUID" and "Invalid ISO date"). |
| `Textarea` | `src/components/ui/Textarea.tsx` | The design's multi-line field (NOTATKA on "Nowy wyjazd"): 1.5px box, 16px radius, 60px floor, top-aligned. Props mirror `ui/Input` deliberately — `label`, `value`, `onChange`, `error`, same generated-id/aria wiring — so a form needs no second convention; it adds `hint`, referenced alongside the error in `aria-describedby` rather than replacing it. A separate component rather than a flag on `Input`, whose box is a fixed `h-[52px]` flex row built around the optional reveal button. |
| `MAX_NOTE_LENGTH` | `src/lib/period-format.ts` | Upper bound on `care_periods.caretaker_note`. Unlike `MAX_TITLE_LENGTH` this one is **also** a database CHECK (`care_periods_note_length`), so the schema holds the guarantee and this constant turns a violation into a 400 and lets the island say so first — change one and you must change both. |
| `MAX_SPAN_DAYS` / `MAX_TITLE_LENGTH` | `src/lib/period-format.ts` | The period bounds, shared by the zod schema and the create-period island so client and server cannot drift. `MAX_SPAN_DAYS` also equals the database CHECK (`end_date - start_date <= 30`, i.e. 31 inclusive) — change one and you must change all three. Deliberately in a module with no runtime imports, so the island does not pull zod into the browser. |
| `countDays(start, end)` | `src/lib/period-format.ts` | Inclusive day count, UTC-pinned. Three consumers: the zod refine, the island's validation, and the period list. |
| `TIMES_OF_DAY` / `TIME_OF_DAY_LABEL` | `src/lib/period-format.ts` | Display **order** and Polish labels for `public.time_of_day`. The order is the enum's declaration order, which is also what `enum_range` generates — two pages rely on it to render a day's slots consistently. |
| `createPeriodSchema` / `periodIdSchema` | `src/lib/schemas/period.ts` | The server-side gate for the create payload, and the uuid guard shared by `POST /api/periods/[id]/token` and `/periods/[id]`. A page that skips `periodIdSchema` answers differently for a malformed id than for a foreign one. |
| `resolveInviteView(...)` | `src/lib/invite-view.ts` | Decides status, title and which body the caretaker page renders. Holds the uniform-failure rule: unknown, tampered, malformed and revoked tokens must all produce one identical answer. Pinned by `tests/unit/invite-view.test.ts`. |
